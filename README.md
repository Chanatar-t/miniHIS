# Mini HIS · LIS Outlab

ระบบโรงพยาบาลขนาดเล็กที่เน้น **งานห้องปฏิบัติการส่งตรวจภายนอก (Outlab)** ครบวงจร ตั้งแต่แพทย์สั่ง Lab, เจาะเลือด, ส่งหลอดให้ Outlab, รับผลกลับทาง HL7, verify แบบ four-eyes ไปจนถึงรายงานผลพร้อม **AI สรุปผลให้แพทย์**

> โปรเจกต์ portfolio ข้อมูลผู้ป่วย แพทย์ และ Outlab ทั้งหมดเป็นข้อมูลสมมติ

## ทำไมต้อง Outlab

test เฉพาะทางหลายตัว (TSH, Vitamin D, tumor marker) โรงพยาบาลส่งไปตรวจที่ Lab ภายนอก ช่วงที่หลอดเลือดออกจากโรงพยาบาลไปแล้วคือจุดที่ข้อมูลหายง่ายที่สุด เช่น หลอดอยู่ที่ไหน ส่งไปกับใบนำส่งไหน ผลกลับมาครบหรือยัง หรือผลที่ outlab ส่งมาตรงกับหลอดไหน ระบบนี้ตามรอยทุกหลอดด้วย accession barcode และ shipment

## วิธีรัน

ต้องมี Node.js 24 ขึ้นไป (ใช้ `node:sqlite` ที่ติดมากับ Node ไม่ต้องติดตั้ง database)

```bash
npm install
npm run dev          # http://localhost:3000  (DB + ข้อมูลตัวอย่างถูกสร้างเองตอนเปิดครั้งแรก)
npm run db:reset     # ล้าง DB (หยุด dev server ก่อน)
```

ผู้ใช้เดโม (หน้า login เลือกได้เลย ไม่มีรหัสผ่าน):

| ผู้ใช้ | บทบาท |
|---|---|
| สมใจ | CLERK เวชระเบียน |
| พว.มาลี | NURSE พยาบาลคัดกรอง (ซักประวัติ) |
| นพ.ธนา | DOCTOR |
| นางสาวพิมพ์ / ทนพ.สมศักดิ์ | LAB (2 คน ใช้สาธิต four-eyes) |
| พญ.วิไล | LAB + สิทธิ์อนุมัติค่าอ้างอิง (พยาธิแพทย์) |
| ผู้ดูแลระบบ | ADMIN (Audit log) |

**คู่มือการใช้งาน + UAT** อยู่ที่ [`/guide`](http://localhost:3000/guide) เปิดได้โดยไม่ต้อง login มีคู่มือแยกตามบทบาท ปุ่ม "ลองใช้เป็น…" และ test case 52 ข้อที่ผู้ทดสอบกดบันทึก ผ่าน / ไม่ผ่าน ได้ทันที ส่วนสรุปผลอยู่ที่ `/guide/uat` (พิมพ์เป็นรายงานได้)

**ตัวช่วยสรุปด้วย AI (ไม่บังคับ)** ใช้ Claude API ใส่ key ใน `.env.local`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

ถ้าไม่มี key หรือ API ล่ม ระบบยังใช้งานได้ปกติ และแสดงสรุปแบบกฎแทน

## ทดสอบ

```bash
npm test                      # unit test: flag ผล, เลขบัตรประชาชน, แยกหลอด, HL7 parser, AI guardrail
npm run build && npm run smoke  # end-to-end 60+ checks บน DB ชั่วคราว (ไม่แตะ DB จริง)
```

`smoke` ยิง HTTP แบบเดียวกับเบราว์เซอร์ที่ไม่มี JS ครอบคลุม flow หลักและกรณีผิดปกติ: สแกนซ้ำ, reject ซ้ำ, ส่ง shipment ซ้ำ, import HL7 ซ้ำ, outlab ปลอมตัว, verify ผลที่ตัวเองลง, ค่าวิกฤตที่ไม่ได้บันทึกการแจ้ง, ผู้ใช้ผิด role ยิง action ตรงๆ, cookie ปลอม

## Design decisions

| เรื่อง | ตัดสินใจ | เหตุผล |
|---|---|---|
| Flag ผล | คำนวณใหม่จากค่าอ้างอิงของโรงพยาบาลเรา ไม่ใช้ flag ที่ outlab ส่งมา | ค่าอ้างอิงขึ้นกับประชากรและวิธีตรวจของแต่ละที่ |
| ค่าวิกฤต | verify ไม่ได้ถ้ายังไม่บันทึกว่าแจ้งใคร ทางไหน | มาตรฐาน HA กำหนดให้รายงานค่าวิกฤตและมีหลักฐาน |
| Four-eyes | ผู้ลงผลกับผู้ verify ต้องเป็นคนละคน ผลจาก HL7 นับ outlab เป็นคนที่หนึ่ง | ลดความผิดพลาดจากคนเดียว |
| HL7 import | idempotent ด้วย MSH-10, outlab ส่งผลได้เฉพาะ test ของตัวเอง, ไม่มีผลที่ตรงเลยให้ rollback | ไฟล์ถูกส่งซ้ำบ่อยในงานจริง |
| แก้ผล | ไม่ลบค่าเดิม เก็บใน `result_amendments` พร้อมเหตุผล ใบรายงานขึ้นว่า "แก้ไข" | ตรวจสอบย้อนหลังได้ |
| แพทย์เห็นผล | เฉพาะผลที่ verify แล้ว | ผลที่ยังไม่ verify ยังไม่ใช่ข้อเท็จจริง |
| แพทย์อ่านผลเอง | ตาราง ผลตรวจครั้งนี้ อยู่บนสุดพร้อมค่าอ้างอิงและค่าครั้งก่อน (↑↓) และใบรายงานรวมทั้ง Visit ส่วน AI พับไว้ใต้ตารางและติดป้าย ไม่บังคับ | AI ผิดพลาดได้ ข้อมูลหลักต้องเป็นค่าจริงที่ verify แล้ว แพทย์ตัดสินใจจากค่าจริง |
| ค่าอ้างอิงเปลี่ยนได้ | ตาราง `test_ranges` แยกเพศ/อายุ มีเวอร์ชันและวันเริ่มใช้ นักเทคนิคฯ เสนอพร้อมเหตุผล พยาธิแพทย์ (สิทธิ์ `can_approve_config` ไม่ใช่ role) อนุมัติ คนเสนออนุมัติเองไม่ได้ ก่อนอนุมัติเห็นผลกระทบกับผลย้อนหลัง 1 ปี | ความรู้การแพทย์ น้ำยา และเครื่องตรวจเปลี่ยนตลอด แต่ต้องมีผู้รับผิดชอบและตรวจสอบย้อนหลังได้ |
| ผลเก่าไม่เปลี่ยนตาม | ตอนลงผลบันทึกช่วงค่าที่ใช้ติดไปกับผล (snapshot) ใบรายงานอ่านจากตรงนั้น | ใบรายงานเป็นเอกสารทางการแพทย์ ต้องแสดงเกณฑ์ที่ใช้ตัดสินในวันนั้น |
| ค่าครั้งก่อน | เทียบตามวันที่มารับบริการ ไม่ใช่ลำดับ id | ข้อมูลที่บันทึกย้อนหลังหรือย้ายระบบมาจะมี id ใหม่กว่าแม้เกิดก่อน |
| AI | ส่งเฉพาะเพศ อายุ และผลที่ verify แล้ว (de-identified), ห้ามวินิจฉัย, ตรวจว่าทุกตัวเลขที่ AI เขียนมีอยู่ในข้อมูลจริง, บันทึกใน audit, ล่มแล้วใช้สรุปแบบกฎ | PDPA และความปลอดภัยของผู้ป่วย |
| Autocomplete สั่ง Lab | ไม่ใช้ AI เรียงตาม test ที่แพทย์คนนั้นสั่งบ่อย | เร็ว ฟรี และคาดเดาผลได้ |
| เลขรัน HN/VN/Accession | `INSERT ... ON CONFLICT DO UPDATE ... RETURNING` | atomic ไม่ชนกันแม้กดพร้อมกัน (ไม่ใช้ `MAX()+1`) |
| สิทธิ์ | ตรวจใน server action ทุกตัว ปุ่มที่ซ่อนมีไว้เพื่อ UX เท่านั้น, ถูกปฏิเสธแล้วบันทึก `DENY` | server action ถูกเรียกตรงได้ |
| Error | ผิดกฎธุรกิจแสดงเป็นข้อความบนหน้าเดิม และ transaction rollback ส่วนบั๊กจริงไปหน้า error พร้อมรหัสอ้างอิง | ผู้ใช้หน้างานต้องรู้ว่าต้องทำอะไรต่อ |
| แพ้ยา | แยก 3 สถานะ: แพ้ / ถามแล้วไม่แพ้ / ยังไม่เคยถาม ลบได้แค่ซ่อน (เก็บว่าใครบันทึก ใครลบ) | "ไม่มีข้อมูล" ต้องไม่ถูกอ่านว่า "ไม่แพ้" |
| สัญญาณชีพ | 1 แถวต่อ Visit วัดซ้ำแทนค่าเดิม แต่ทุกครั้งที่บันทึกเก็บค่าไว้ใน audit, ตรวจช่วงค่าที่เป็นไปได้ และความดันตัวล่างต้องน้อยกว่าตัวบน | กันพิมพ์ผิด (1200 แทน 120, กรอกสลับช่อง) |
| Database | SQLite (`node:sqlite`) + SQL ตรงๆ ไม่ใช้ ORM | clone แล้วรันได้ทันที SQL อ่านและอธิบายง่าย |

## ถ้าจะขึ้น production

- PostgreSQL (schema เป็น SQL มาตรฐาน แก้ไม่มาก) และ connection pool
- Login จริงผ่าน SSO / LDAP ของโรงพยาบาล
- รับ HL7 ผ่าน MLLP/SFTP แทนการอัปโหลด, รองรับ ORU status `C` (corrected), ส่ง ORM ไป outlab
- FHIR API: map เป็น `ServiceRequest` / `Specimen` / `Observation` / `DiagnosticReport`
- กระทบยอดใบแจ้งหนี้รายเดือนของ outlab กับ shipment
- Patient portal: คนไข้ดูผลของตัวเองพร้อมคำอธิบายภาษาง่าย (แพทย์เป็นคนกดปล่อยผลที่อ่อนไหว)

## แผนพัฒนาต่อ (ยังไม่ได้ทำ)

เรียงตามความสำคัญ

1. **จบการตรวจ / ปิด Visit**: หลังรายงานผลครบ แพทย์เรียกผู้ป่วยฟังผล แล้วกด "จบการตรวจ" (modal บนหน้าผู้ป่วย) บันทึกสรุปผลที่แจ้ง คำแนะนำ วินิจฉัย และนัดครั้งถัดไป (วันที่ + สิ่งที่จะตรวจ) สถานะ Visit เป็น **เสร็จสิ้น** ใบรายงานผลแสดงคำแนะนำและวันนัด จบได้แม้ผล outlab ยังไม่ครบ (เตือน "ยังรอผล n รายการ" และแจ้งแพทย์เมื่อผลที่ค้างออก) Visit ที่ไม่ได้สั่ง Lab ก็จบได้ ตอนนี้สถานะค้างที่ "รายงานผลครบ" หรือ "รอพบแพทย์"
2. **บันทึกแพทย์ + วินิจฉัย ICD-10**: ประวัติ ตรวจร่างกาย วินิจฉัย ICD-10 (หลัก/รอง) และหัตถการ ICD-9-CM การเบิกทุกสิทธิต้องมี ICD-10 ทุก Visit
3. **การเงิน / ค่าใช้จ่าย**
   - ราคาตามสิทธิ: `lab_tests` มี `price` และ `cost` แล้ว แต่ยังไม่แยกราคาตามสิทธิ (บัตรทอง / ประกันสังคม / ข้าราชการ / ชำระเอง) และยังไม่มีรายการที่เบิกไม่ได้หรือต้องจ่ายส่วนเกิน
   - ใบแจ้งค่าใช้จ่ายต่อ Visit: รวม Lab ค่าบริการ และ (อนาคต) ยา แยกยอดเบิกได้และยอดผู้ป่วยจ่ายเอง
   - รับชำระและใบเสร็จ: เลขใบเสร็จรันแบบ atomic, ยกเลิกใบเสร็จต้องมีเหตุผลและผู้อนุมัติ, ปิดยอดประจำวันของแคชเชียร์
   - เบิกจ่าย: ส่งออกข้อมูลเบิก สปสช. (e-Claim / 43 แฟ้ม) ประกันสังคม และกรมบัญชีกลาง (ต้องมี ICD-10 จากข้อ 1)
   - ต้นทุน Outlab: กระทบยอดใบแจ้งหนี้รายเดือนของ outlab กับ shipment และกำไรต่อ test (`price - cost`)
   - role ใหม่ **การเงิน (CASHIER)** และรายงานรายได้รายวัน/รายเดือนแยกตามสิทธิ
4. **ข้อมูลลงทะเบียนเพิ่ม**: ที่อยู่ (ใช้ตอนเบิก) ผู้ติดต่อฉุกเฉิน กรุ๊ปเลือด โรคประจำตัว
5. **ยกเลิก / แก้ Visit**: เปิดผิดคนหรือเลือกสิทธิผิด ต้องมีเหตุผลและบันทึก audit, ยกเลิกไม่ได้ถ้ามีการสั่ง Lab แล้ว
6. **นัดหมาย / ติดตามผล**: เช่น นัดเจาะเลือดซ้ำอีก 3 เดือน พร้อมรายการนัดของแต่ละวัน
7. **จอเรียกคิวหน้าห้องตรวจ**: หน้าจอแยกต่างหาก ไม่ใช่หน้า /patients
8. **สำรองข้อมูล**: backup ไฟล์ SQLite อัตโนมัติรายวัน (`VACUUM INTO`) และทดสอบการกู้คืน
9. **ระบบยา / ห้องยา**: สั่งยา ตรวจแพ้ยาอัตโนมัติจากตาราง `allergies`, ยาซ้ำซ้อน, จ่ายยา และตัดสต็อก (งานใหญ่ที่สุดในรายการ)
